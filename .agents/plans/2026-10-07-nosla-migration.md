# Xboard 迁移至 NoSLA

## 目标与边界

将腾讯云 `170.106.143.23` 的 Xboard、CloudBridgeRelay、Caddy 和订阅辅助 Mihomo 迁移至免密 SSH 目标 `NOSLA`（`216.23.116.56`）。不迁移腾讯云上的其他项目，不调整指向其他主机的 DNS、邮件及根域名记录。客户端平台开发保持暂停。

## 已验证基线

- 源目录 `/opt/xboard-test`；SQLite 及 WAL、插件、补丁、主题、引导配置为绑定持久化；Redis 与 Caddy 使用 Docker 卷。
- 数据库 quick_check 为 ok：4 用户、2 套餐、2 订单、133 节点、8 插件；不输出用户、密钥或订阅内容。
- 源 Xboard 内存约 165MiB，Caddy 23MiB、辅助 Mihomo 11MiB；目标 Debian 13 x86_64、929MiB 内存、27GB 可用磁盘、无 Docker/交换空间，80/443 空闲。
- 使用源容器对应的确切镜像导出导入，不拉取浮动 latest，不重新构建。
- 现有客户端入口 `https://cloud.microsoftnexushub.top:8443` 必须保留。源 443 被其他项目占用，8443 使用自签证书，直接橙云 443 当前返回 502。

## 域名分工

| 域名 | 职责 | 目标 |
| --- | --- | --- |
| cloud.bingcn.site | 网页、注册、邀请、下载入口 | NoSLA，橙云，HTTPS 443 |
| api.bingcn.site | API、订阅入口 | NoSLA，橙云，HTTPS 443 |
| origin.bingcn.site | 运维直连与源站验证 | NoSLA，保留仅 DNS，HTTPS 443/8443 |
| cloud.microsoftnexushub.top | 既有客户端兼容与备用入口 | NoSLA，橙云，HTTPS 443/8443 |

引导池包含健康 API 与兼容域名；`app_url` 指向公开网页域名。通过实际字段依据修改后台配置，保留返佣规则及其他运营设置。

## 执行顺序与所有权

由主控独占远端配置、数据库、DNS 及项目聚合文档；独立 Agent 只读审阅计划与脱敏验收证据。

1. 只读盘点源卷、容器可写层、辅助代理依赖、数据库结构与目标资源；备份源运行配置、绑定目录、容器必要主题和确切镜像。
2. 在目标安装官方 Docker/Compose，配置 2GB 交换空间；Xboard 保持低资源配置并限制内存，代理端口保持回环。传输均通过 SSH，秘密文件不回显、不入仓库。
3. 部署候选运行目录、持久卷和确切镜像。预签发覆盖相关主机名的可信证书；优先现有 DNS-01 凭据，若权限不足只切相关域名后用 HTTP-01，避免削弱 Cloudflare TLS。
4. 源停止 Xboard 和辅助代理写入，Redis 正常持久化后归档最终数据；校验传输 hash、SQLite 完整性与所有表行数。目标首次启动前调整公开域名配置，避免定时任务并行写入。
5. 验证目标回环服务、`--resolve` 源站 TLS、主题、插件、引导 JSON 和公开 API。新 Caddy 同时提供 443 与 8443，保护兼容入口。
6. 在已登录 Cloudflare 浏览器中仅编辑表列记录，保留 DNS 快照；确认没有覆盖源端口的遗留规则。切换源站后，旧入口停止业务写入，必要时转发至新源，确保唯一数据库主节点。
7. 对公网网页、API、注册路由、引导池及 TLS 连续验收；核对内存、重启计数及源无写入。不得用真实付款或主动创建邀请替代迁移验证。
8. 评估官方 cf CLI 安装及最小认证；不新增未经确认的广泛 OAuth 权限。同步部署说明、架构与变更记录，HLG dry-run/apply，提交推送本任务文档。

## 验收与回滚

验收：所有 SQLite 表行数及完整性一致（明确列出的配置修改除外）；所有运行镜像 ID 一致；插件及绑定资源 hash 一致；目标服务健康、443/8443 可信 TLS、公网 API 200、app_url 与引导池正确，DNS 控制台目标为 NoSLA。不以源站响应代替公网验证。

切换前失败：目标保持隔离，源继续服务，恢复必要 DNS 临时改动。切换后失败：先停止目标写入并备份其数据库/Redis，将目标新增数据同步回源后启动源服务，再使用可信源站配置、相关域名 8443 回源规则并恢复 DNS；不得用切换前快照覆盖新写入。保留旧主机及加密通道内的权限受限备份，未获授权不删除。证书签发、资源不足或数据一致性失败时停止切换并修正，不宣称完成。

## 独立审阅约束

- 证书优先 DNS-01 预签发；权限不足时 HTTP-01 只能用于冻结后的维护窗口，不提前切换生产 DNS。所有入口使用公开可信证书，避免 Origin CA 无法满足直连信任。
- 源冻结覆盖容器内 Web、队列和定时任务，正常停止整个 Xboard 容器。核验 Redis RDB/AOF 状态并复制完整卷；停止后对 SQLite 与 WAL 一起归档，计算数据库所有表内容摘要及绑定文件摘要，目标启动前比对。
- 回滚先停目标 Xboard/Mihomo，完整一致数据库和 Redis 卷回传源，恢复域名配置，再验收源并恢复 DNS；目标入口在 DNS 传播期间转发到源，保持单一写入节点。
- 资源预算：Xboard 512MiB、Caddy 128MiB、Mihomo 128MiB；保留系统余量，保持源低资源工作进程。观察内存、swap、OOM、重启及定时任务，不把 swap 当容量验收。
- `app_url` 为唯一预期后台设置差异；不额外创建 `subscribe_url`，订阅以访问域名生成。其他设置、表内容保持摘要一致，运行生成的日志/统计差异单列。

## 实施验收

四条 A 记录已通过浏览器切至 NoSLA，相关橙云主机名专用严格 TLS 已部署；无 Vercel 访问依赖。34 表与 35 绑定资源启动前一致，运行后唯一设置差异为 app_url。详见 docs/SERVER_DEPLOYMENT.md 及脱敏验证目录。

Xboard 512MiB 初始启动出现 OOM/超时，调整为 768MiB、内存加交换1280MiB、CPU1，.env 显式设置三类队列上限1后重建，最终 OOM=false、restart=0。资源预算与容量限制以部署说明为准。

回滚必须考虑旧443被其他项目占用：源8443已准备四域名可信证书；回传目标最新一致数据并启动源后，还需设置仅匹配相关主机名的 CF Origin Rules 回源8443，再恢复DNS。不能直接恢复旧自签Caddy。

独立收口审阅已补充：公网边缘证书与源站证书分开记录；源站 TLS 从腾讯云直连 NoSLA IP 核验；回滚先冻结业务再在 Redis 运行时 SAVE，随后停容器；回滚上游固定源 IP 与 SNI，旧复制证书需回滚当天核验有效期并续签。CloudBridgeRelay 为 Xboard 内插件，其绑定资源及 v2_plugins 配置摘要一致。
