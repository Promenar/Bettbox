# Flutter 共享代码与平台验收工作包

日期：2026-09-22。邀请入口已完成，工作进入业务验证与平台适配。

## 用户目标与工程决策

- 完成邀请返利的后续验证，推进 iOS、macOS、Windows 适配。
- 维持单仓库、共享 Dart 业务代码和 UI；平台差异置于原生目录与明确的能力边界，不建立长期分叉的三套平台业务分支。
- 当前工作沿用 `feature/m1-account-subscription`。需要隔离的大型功能可建立短期工作分支并合回共享主线，不以操作系统作为长期分支策略。
- 用户有 iPhone，Apple Developer 团队尚未准备好；iOS 先完成可以独立验证的工程准备，真机 VPN 签名和商店能力单独验收。

## 已验证问题与关键路径

1. `CheckoutPage` 在所有平台无条件构造 WebView；Windows 未注册该插件实现。桌面应按 PRD 使用系统浏览器，Android 继续支持嵌入式收银台。
2. macOS 安全存储已使用 flutter_secure_storage，但 entitlements 未含该插件文档要求的 Keychain Sharing 配置；按当前插件说明补齐，并将签名后的持久化验证保留为原生验收项。
3. 邀请业务需要验证归属、佣金计算和重复结算；先研究现有服务器代码，以隔离数据库/缓存/邮件/队列或事务回滚方式执行，不调用真实支付网关、不修改既有账户余额。
4. 仓库为公开 GitHub 项目，既有 CI 仅由发版 tag 触发且含发布步骤；平台构建必须有独立的无发布验证入口。
5. iOS 不仅缺原生目录：内核当前按 Android 动态库/桌面进程两路选择，iOS 会落到空桌面服务；Go bridge 也只有 Android 和非 Android 两种模式。完整移植需独立 Packet Tunnel 内核桥接，不能用占位接口声称完成。

## 文件所有权与实施

- 主控独占：`lib/views/store/checkout_page.dart`、新增收银平台策略/测试、macOS entitlements、项目构建验证入口及文档/HLG。
- 独立只读代理：研究 Xboard 邀请验证隔离方法；源码修改完成后由未施工审阅者复核平台分支与测试。
- 先复现桌面 WebView 异常，补平台行为测试，再修改实现；校验 Android 原行为、桌面外链失败提示、二维码路径、重绘不重建 WebView。
- 必要构建执行方案明确后再执行：macOS 使用本机 Apple 工具链；公开 Windows 确定性编译优先 GitHub 标准 Runner；真实 Windows 设备联调另行落到已核验主机。

## 验收与边界

- 本地 Flutter 单元/Widget 回归与相关静态分析通过。
- Windows/macOS/Linux 收银页不创建嵌入式 WebView，外链以系统浏览器打开，取消/失败具有可理解反馈。
- Android WebView 可复用同一控制器，刷新不重复加载；二维码收银不受平台分支影响。
- macOS plist 语法校验通过；Keychain 签名与冷启动恢复只能用实际原生运行验证。
- 邀请服务器验证报告明确调用层级、数据库回滚结果、缓存/队列/邮件隔离及未覆盖范围。
- PDEC 缺失；平台构建方案需形成具体可审阅输入，按授权和 remote-development 执行，不把发版 tag 当测试入口。
- iOS 未有开发者团队和真机签名时，不声称隧道、IAP、后台恢复或 App Store 分发已完成。

## 回滚

客户端变更可以按本任务提交回退；不替换现有发版流程。服务端验证不改变既有运营配置与资金记录，测试产生的非持久数据须确认回滚或隔离保存，不能混入正式业务结论。
